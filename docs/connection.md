# 连接、身份、错误与等待

## 建立连接

服务地址可省略：优先使用已保存的部署地址，没有保存地址才连接 RQAMS 官方地址 `https://www.ricequant.com`。首次连接私有化部署或切换部署时，用 `base_url`、`RQAMSH_BASE_URL` 或 `rqamsh --base-url <地址>` 指定目标地址，完整优先级见下文。模块级 `rqamsh.init` 与显式 `Client` 使用相同业务方法；建议用上下文管理器释放连接：

```python
from rqamsh import Client

with Client(
    token="<令牌>",
    timeout=60,
    wait_timeout=300,
    poll_interval=1,
) as client:
    result = client.products.list()
```

私有化部署再传对应地址，例如 `base_url="https://ams.example.com"`。CLI 全局选项必须写在业务子命令前：

```console
rqamsh products list
rqamsh --base-url https://ams.example.com products list
rqamsh --token @agentkey products list
rqamsh --help
rqamsh schema
rqamsh trades upload --help
```

CLI 地址优先级为 `--base-url` > `RQAMSH_BASE_URL` > 设置文件 > RQAMS 官方地址；令牌与工作空间也支持对应的 `RQAMSH_TOKEN`、`RQAMSH_WORKSPACE_ID`。Python 的 `Client` / `rqamsh.init` 不读取这些连接环境变量：通过参数提供，地址或令牌省略时读取设置文件，地址再回退官方地址。下文 Python 示例默认已用 `rqamsh.init` 建好模块级客户端，显式 `Client` 的示例把实例绑定为 `client`。

显式提供令牌不会改变地址的解析顺序；切换部署或使用另一部署的令牌时，同时明确目标地址，不能假定新令牌会让地址自动回退官方部署。保存身份的部署绑定检查只保护从设置文件复用的令牌，不替显式令牌推断所属部署。

<a id="token-auth"></a>

## 认证与令牌

认证只有 Bearer 令牌：从 AMS 平台或管理员取得，由客户端随每个请求以 `Authorization: Bearer <token>` 发出。令牌的签发方式与有效期由 AMS 平台决定；客户端不代办账号密码登录，也不会续期或打印令牌。

本机首次使用的默认入口是 CLI 浏览器登录，由 Agent 主动执行首次只读命令，用户在本机页面填 key，保存后继续原命令；完整引导与环境分支见[首次使用流程](guide.md#使用方式用户说业务agent-读文档)。缺少连接环境变量不等于缺少可用连接方式，不预先要求地址与空间 ID。已有身份按下述优先级复用，需要重新登录时执行 `rqamsh auth`。

只有明确远程、无图形或无人值守环境才设 `RQAMSH_AUTO_LOGIN=0` 并使用安全注入；已提供受限文件或环境变量时可直接使用。令牌不要贴进对话：

- `--token @文件`：文件只放令牌本身，UTF-8，客户端会去掉首尾空白与行尾回车；适合自动化。
- `RQAMSH_TOKEN`：由运行环境注入；同用户进程或子进程可读，注意运行环境隔离。
- `--token <字面值>` 会进入 shell 历史、进程命令行和可能的终端/CI 日志，只适合临时调试。

登录校验时客户端读取该令牌的成员空间：显式给出 `workspace_id` 时必须命中成员列表，没有显式空间则直接保存成员列表首项（`data[0]`，服务端原序，不排序、不按 AMS 权益筛选）。令牌提交一次即完成登录，页面不再要求二次选择空间。没有成员空间、显式空间不属于该令牌、或保存失败都会报错并保留原有设置；默认空间规则见[工作空间](workspaces.md#默认工作空间与切换)。令牌不被页面回显，不进入地址或命令输出；校验通过后持久化在下述本机设置中。登录等待超时后，该登录页后续提交不再生效，需要重新运行 `rqamsh auth`。

同一登录只完成一次保存：重新提交令牌或登录结束后，之前在途的提交不再生效，旧页面不能覆盖已保存的身份。

登录信息默认保存在用户目录的 `rqamsh_settings.json`（`RQAMSH_SETTINGS` 可改路径），含明文令牌，应保持仅当前用户可读，不要提交或共享；权限仍由 AMS 平台判定，设置文件不是授权凭证。令牌优先级为显式 `--token` > `RQAMSH_TOKEN` > 设置文件；显式提供令牌时不会沿用设置文件中的工作空间。

保存的令牌与空间只用于其保存的部署地址。换协议、主机、端口或部署路径时，客户端在发请求前报 `invalid_config`，要求重新运行 `rqamsh auth` 或显式提供目标部署的令牌；不把旧令牌自动发送给新部署。地址首尾空白、尾斜线、默认端口及省略 `/api/rqams/v2` 不影响同一部署的判定。旧设置文件如果只有令牌、没有部署地址，也必须重新登录或显式提供令牌，不能推断它属于官方地址。

Python 的 `token=` 可省略：省略时读取设置文件，没有可用设置则报 `invalid_config`；`rqamsh.init()` / `Client` 不自动打开浏览器，本机首次先完成 CLI 登录，之后再复用设置。显式传入时只接受非空字符串；类型错误、空值或内部换行在本地拒绝，不发请求。

`workspace_id` 可省略：复用保存令牌且同一部署的设置文件已有最后选择的空间时直接使用；否则首次业务请求前先读取当前用户的成员空间（同一部署的用户服务 `GET <部署>/api/user/v1/workspaces`，只带 Bearer 令牌、不带 `X-AMS-Workspace`、不跟随重定向）——列表非空时使用服务端本次返回的首项 `data[0]`，没有任何成员空间则报 `resource_not_found`，不发业务请求。首项严格按服务端原序取第一个：客户端不排序、不按名称或 ID 取最小项、也不按 AMS 权益筛选；首项缺少所需权益时由服务端拒绝，客户端不会改用第二项重试。旧的令牌上下文接口已不再提供，客户端也没有对应回退。私有化部署若业务接口返回 422 `No workspace specified`，说明本次请求没有目标空间，需要显式传入 `workspace_id` / `--workspace-id`。仅复用保存身份的客户端会把最后选择写回设置文件，包括显式传递、`workspaces.use` 成功及自动选中首项；临时令牌不会读取或改写保存的空间。完整的默认、写回与切换规则见[工作空间](workspaces.md#默认工作空间与切换)。

## 工作空间是什么

工作空间是服务端的数据分区，不是客户端可以自行创建的容器；本版只使用当前用户已是成员的空间。下面 8 条给出判断「某个资源能否访问、能否写入」时的空间边界，每条给出可核对的结论；成员空间的读取与目标空间的重设见[工作空间](workspaces.md)。

1. **工作空间写在每条资源记录上，客户端的 `workspace_id` 只选择请求分区、不是凭证。** 产品、产品组、权限记录、标签、自定义标的、风控条款与自定义指标等记录都带 `workspace_id` 字段，查询、唯一约束与权限判定都以它为准；客户端传入的 `workspace_id` 决定请求落到哪个分区，它本身不构成身份证明。
2. **每个业务请求都必须携带工作空间。** 服务端从 `X-AMS-Workspace` 请求头取空间 ID：缺失报 `No workspace specified`，非法报 `illegal workspace`。Harness 用 `workspace_id` 设置该头，也可用 `workspaces.use` 在当前用户的成员空间之间选择目标。构造客户端或启动 CLI 时可以省略工作空间：显式或已保存的空间优先，否则自动使用成员列表首项，没有任何成员空间时报错；首项缺少所需权益由服务端拒绝，客户端不自动换成第二项，规则见[工作空间](workspaces.md#默认工作空间与切换)。若业务接口返回 422 `No workspace specified`，说明本次调用没有目标空间：核对地址与所选空间是否属于该部署，仍无法确定时由管理员提供成员空间 ID 并显式指定，不能猜测 ID。
3. **可见性 = 空间 ∩ 权限。** 你只能看到自己创建的、或被分享给本人的产品/产品组；空间内存在既不代表能看到，也不代表可写，见[可见不等于可写](permissions.md#可见不等于可写)。
4. **唯一约束以工作空间为范围。** 产品名称、账户名称与基金代码在空间内唯一，标签在同用户同空间内唯一；跨空间可以重名，因此「名称已存在」只在当前空间成立。
5. **跨空间资源被拒绝。** 平台对请求涉及的产品/产品组逐个核对 `workspace_id`，有任一不属于当前空间就整体报错（原文形如「请检查所选以下产品(组)是否存在于当前空间」）；自定义标的混入其他空间的 ID 时在预检阶段整体失败、不写入。
6. **分享受空间约束。** 权限记录按 `(user_id, workspace_id, resource_type, resource_id)` 组织；被分享者必须已属于该空间，否则逐项报「您所操作的用户没有使用该工作空间的权限」；`admin` 权限不能被分享。`products.list(member_user_id=…)` 筛的是「我分享给该成员的产品」，不是空间内任意成员的产品。
7. **令牌关联用户，一个用户可以是多个空间的成员；`use` 只改目标分区。** 成员空间列表来自同一部署的用户服务 `GET <部署>/api/user/v1/workspaces`，不要求也不发送 `X-AMS-Workspace`，返回记录字段见[工作空间 list](workspaces.md#list)。列表只说明成员关系，不说明 AMS 权益或资源权限；选择、拒绝非成员 ID 与失败不改状态的规则见[工作空间 use](workspaces.md#use)。
8. **空间成员关系由 AMS 与用户服务维护；资源上的 `workspace_id` 只读。** 客户端不能通过改请求头访问自己不是成员的空间；服务端仍会按请求头、成员关系与 AMS 权益逐项判定。资源记录里的 `workspace_id` 由连接身份决定，不接受客户端写入。`workspace_id` 的只读标注见[产品字段](fields/products.md)。

## Python 与 CLI 调用约定

Python 有两种等价写法：除本页的连接示例外，各业务页示例统一用模块级调用——先 `rqamsh.init(token=...)` 建立默认客户端（地址省略时先读设置文件，再回退官方地址；首次连接私有部署或切换部署时传 `base_url`，见[建立连接](#建立连接)；`workspace_id` 可省略，默认按保存的最后空间或成员列表首项选择，见[认证与令牌](#token-auth)），之后直接写 `rqamsh.<业务块>.<操作>(...)`，结束时 `rqamsh.close()`；需要并行多个身份时改用上面的显式 `Client`，各自持有实例，不共享模块默认客户端。未初始化就写 `rqamsh.<业务块>.<操作>` 会得到 `not_initialized`。

签名按参数顺序列出参数名、类型与默认值，例如 `rqamsh.balances.get(resource_or_resources: str | list[str], *, date: str | None=None, ...)`。调用时一律显式写成 `参数名=值`，例如 `rqamsh.balances.get(resource_or_resources='授权测试产品', date='2026-01-05')`，不依赖位置顺序；CLI 使用同名的 `--参数名`。签名只描述参数本身，不表示可省略语义：默认值 `None` 的含义由各操作说明给出。

CLI 的全局选项必须写在业务子命令之前，块名与操作名把下划线换成连字符：

```console
rqamsh --base-url https://ams.example.com --token @agentkey balances get --resource-or-resources "授权测试产品" --date "2026-01-05"
```

- CLI 的地址来源优先级见[建立连接](#建立连接)，令牌与工作空间的来源、部署绑定和文件读取方式见[认证与令牌](#token-auth)。`--timeout`、`--wait-timeout`、`--poll-interval` 只作为全局选项传入。
- 参数名同样把下划线换成连字符（`--order-book-id`）。方法 `data` 参数使用 `--input`（别名 `--data`），值支持 JSON 字面量、`@file.json` 与 `@-` 读 stdin；`trades upload`、`valuation_reports upload` 的 `data` 也可直接给文件名。
- 数组与对象写 JSON 文本，布尔写 `true`/`false`：`--fields '["date","total_equity"]'`、`--drilldown false`。方法名、块名或参数名写错以 `invalid_arguments` 失败，不会猜默认值。
- `rqamsh schema` 与各层 `--help` 无需连接即可离线查看块、操作与参数；输出与错误语义见下节。
- 各业务页的操作标题就是 API 方法名（如 `## list`、`## upload_file`），跨页链接以这些标题为锚点；改动标题需同步所有引用。

## 身份与权限边界

`workspace_id` 是 24 位十六进制字符串，具体边界见[工作空间是什么](#workspace)。身份只来自[Bearer 令牌](#token-auth)，没有第二个入口；`workspace_id` 本身不是登录凭证，不能仅凭填对空间 ID 获得访问权。省略 `workspace_id` 时默认按保存的最后空间或成员列表首项选择（见[认证与令牌](#token-auth)）；用一个自己不属于的空间 ID 也不会读到该空间的数据。不要拿猜出来的 ID 反复试探他人的分区。

令牌过期后服务端会拒绝请求，需要重新取得，客户端不会替你续期。仅在用户授权的资源范围内调用，上传、覆盖、删除、重算前确认目标与影响范围。

客户端不判断读取级别：解析资源后直接发出请求，越级由平台拒绝并原样返回错误（HTTP 403 映射为 `permission_denied`，文案为平台原文）；级别与逐操作下限见[资源权限](permissions.md#逐操作最低权限级别)。解析资源与列出资源时，只保留当前身份能读到的对象；客户端不查授权行、不做归属校验，越权与否由平台判定。

客户端资源筛选只用于减少选错对象的风险，不构成身份认证、权限拦截或租户隔离；绕过 Harness 直接调用接口时，也不能假设仍有平台级隔离。需要可信身份与租户隔离时，必须由 AMS 管理员提供相应入口；不要绕过客户端去探测或操作不可访问的资源。

## 单字符串资源选择器

`resource` 接受当前身份可访问资源的 ID 或名称。资源类型有 product、product_group、asset_unit；产品/组名称来自 name，资产单元名称来自 symbol。账户只是产品里的账户名称，不能当作独立 resource。

同时按 ID 与名称匹配：找不到时报不存在或不可访问；多匹配时报歧义，并给出可访问候选的类型、ID 和名称。使用候选中的唯一 ID 消歧，不根据名称猜测目标。选中目标仍需符合操作支持的资源类型；产品写操作不会对产品组成员广播。

解析一个资源会先列举当前空间的产品、产品组与资产单元，再只读取命中项的详情；命中项唯一时通常只需「3 个集合请求 + 1 个详情请求」，不会为整个空间逐项拉详情。`products.list`、`product_groups.list` 与 `asset_units.list` 需要完整目录，客户端会核验空间内每个资源的详情；这是各列表操作自己的行为，可见性过滤与返回字段见[产品 list](products.md#list)、[产品组 list](product_groups.md#list) 与[资产单元 list](asset_units.md#list)。空间内有上百个产品时，全量列举仍应少做。同一客户端在 5 分钟内复用同一份索引与详情缓存，不会每次调用都重新列举；发生任何写入请求之后、以及切换空间之后，已有缓存立即失效，下次解析重新列举；**不改动产品、产品组与资产单元集合的调用不会让它失效**，包括少数用 POST 传参的批量查询（批量上一日概览、批量对账清单、字段最早可用日期等）与挂在资源路径下但只增删任务记录的端点（业绩归因任务的提交与删除）。多步任务先解析一次目标资源并记下 ID，后续直接传 ID；不要为每一步启动新的 CLI 进程。

`reconciliation.list` 的 `resources` 是字符串数组：一次目录快照解析全部成员，重复项去重并保持首现顺序；只支持产品，任一成员不存在或有歧义时整个调用失败，不静默跳过。

`custodian_events.upload_file` 的 `resources` 同样是字符串数组，只支持产品：任一成员不存在或有歧义时整个调用失败，不会只导入其中一部分产品；成员是否可写由平台判定。

需要一次处理多个资源时，按下面的策略提交，避免把时间重复花在解析上：接口本身接受资源数组（如 `resources` 数组）时，按 10~20 个一批提交，不要一个资源一次调用；只接受单个资源的接口，按 10~20 个并发提交，不要串行排队等待。两种做法不要同时拉满，解析本身已在并发进行，叠加时以平台的承受能力为上限。同一进程内只要先完成一次解析（或一次数组调用），后续调用即可复用同一份目录，不要在循环里逐个资源重新解析。多产品 × 多维度时先固定一个维度、一次覆盖全部产品，再换下一个维度，不要逐个产品走完全部维度。

资产单元属于一个产品，名称使用 `symbol`，ID 是单元记录 ID，不是证券代码。对资产单元或持仓单操作前，应确认其归属产品，避免把同名的不同单元混用。

### 资源归属与写入约束

自定义标的须属于当前工作空间且其产品可访问；无归属产品的历史标的可在空间内读取，但仅创建者可写。改变归属需同时具有原标的与新产品写权限。批量删除中任何 ID 不存在或无权时，应先修正输入。下载估值源文件时，报告 ID 必须属于指定产品；不得把其他产品的报告 ID 配在当前产品下。写入与分享所需的身份和级别见[资源权限](permissions.md)。

## 等待任务与判断完成

业务调用会按需等待 AMS 任务或尚未就绪的结果。单请求默认等待 60 秒，总等待默认 300 秒，查询间隔默认 1 秒；Python 使用 `timeout`、`wait_timeout`、`poll_interval`，CLI 使用子命令前的 `--timeout`、`--wait-timeout`、`--poll-interval` 配置。服务端接受请求只表示它开始处理或结果尚未就绪，不表示业务已经成功完成。单次调用的墙钟可能超过 `wait_timeout`，因为解析与业务请求各自有自己的等待预算。

调用方只需按三种结局处理：

|结局|客户端行为|典型场景|
|---|---|---|
|返回结果|返回服务端 JSON、文件元数据或落盘结果|查询、导出|
|等待超时|抛 `wait_timeout`，附服务端最后状态与诊断；只表示停止等待，**不代表服务端取消或失败**|长耗时计算、上游数据尚未就绪|
|明确失败|抛对应错误码并保留服务端原文|计算失败、权限不足|

排队、任务标识与轮询间隔由客户端内部处理，任务状态轮询与 202 重查由客户端自动处理；重查只发生在这两类上，除此之外的未就绪情况不会自动重查——普通 HTTP 200 响应里业务内容未就绪或不全时，需要调用方按各业务页说明自行重试。传输错误（`transport_error`、`wait_timeout`）与一般失败直接抛出，不会自动重试。结果未知时，写请求不会被重复提交：无 task_id 的写请求抛 `pending_without_task`，绝不重放。

实际返回可能是 `{"status":"SUCCESS","data":...}`；不会为了统一形状把 data 自动拆包。提交/上传成功只说明该业务响应达到对应终态，**不等于下游估值计算已完成**；必要时用 compute_state 或读取等待结果。客户端等待超时只表示停止等待，不表示服务端取消或失败；应保留诊断，避免重复提交写操作。

<a id="unready-inputs"></a>
读到空结果、缺失项或空字段时，先按[估值主线](index.md#valuation-lifecycle)理解结果依赖，再分清原因。不要把未就绪当作零值，也不要当作「不存在」或「没有持仓」。计算状态与所需结果的可读性必须分别检查：

|观察到的情况|下一步|何时结束本次等待|
|---|---|---|
|产品或分析任务仍在计算，或所需结果仍在准备|产品用 `products.compute_state`，分析按对应任务查询；等待后重读同一对象、日期与口径的结果，不反复提交写请求|所需结果可读、明确失败，或达到整体等待上限|
|产品状态为 `normal`，但目标实时截面或字段仍缺失|重读同一结果；批量缺项可用单资源同口径读取取得诊断，区分截面准备与缺输入；不能仅凭 `normal` 宣布完成|结果可读、取得明确原因，或达到整体等待上限|
|计算状态或逐项结果明确失败|保留目标、任务标识、错误原文及原因；需要修改输入或重算时遵守对应写入授权|结束盲目重试，报告失败及处理条件|
|已确认缺少基准、业务资料或其他必要输入|说明缺什么及其影响，按对应操作取得授权后补齐，再读回；不编造输入|记录阻塞原因，缺输入不靠等待解决|
|达到本次整体等待上限|保留原请求、已就绪结果、未完成项、最后状态与可用错误；说明服务端可能仍继续处理|结束本次等待，不把超时说成失败或取消，也不把部分小计说成全量结果|

普通 HTTP 200 的业务未就绪由调用方维护整体截止时间，并按配置的查询间隔重读；每次调用各自的 `wait_timeout` 不会自动构成整个用户任务的等待上限。不能只查询几次就视为超时，也不能通过不断重置单次预算无限等待。

成员或批量形态的返回里，先核对请求集合与返回集合的差集，再结合逐项错误和操作的筛选规则判断缺项。头寸成员视图与数组形态的 `pending_valuation` 是请求中未返回且不在 `error_messages` 中的成员，并非服务端确认的计算中清单；可能需要补算，也可能尚未产出实时截面或存在不可补算的未就绪原因。`error_messages` 保留服务端给出的失败原因，两者都空才说明这些形态的请求成员已返回，所需字段及日期仍要核验；其余批量操作要自己按请求集合逐项对账。不要把缺项当作「已不在组内」「已删除」或「没有持仓」。

确定性省略不会因重试出现：成员生命周期与请求区间无交集、可见性与权限过滤、参数投影各有自己的判定条件，与计算未就绪不同。原因属确定性缺口时，把换范围、换区间或口径、或接受缺口并逐项标注的可选方式一并给出，由调用方决定；不要替它改口径后就地交付。

返回结果处于运行态（任务仍在计算、尚未给出终态）或业务上尚未就绪时，必须等到终态（成功或失败）或本次等待上限；不得改用其他日期或其他口径的结果替代当日结果——例如用上一交易日概览或邻近日期报表顶替当日结果。中断等待不等于任务失败：重新提交前先复读原请求的结果。

`wait_timeout` 限制客户端对传输与结果的等待，不是业务取消或事务回滚。域名解析、网络建连、本地文件读写可能使实际耗时超过设定值；已提交的任务仍可能继续执行。调整等待时间前先确认原请求的结果，不应盲目反复提交。

不同操作的耗时差异很大（查询、导出与重算从提交到终态的等待时间可能相差数倍），等待超时只表示停止等待，**不代表任务失败**。默认单请求等待 `timeout=60` 秒、总等待 `wait_timeout=300` 秒、查询间隔 `poll_interval=1` 秒，也可在建立客户端或使用 CLI 全局选项时调整；把这类耗时当作故障并重发写入，是常见的错误处置。

连接只访问配置的 AMS 地址，不跟随重定向；HTTPS 保留证书校验。默认直连，不使用环境中的 HTTP 代理或自动读取其他本机认证配置。若环境要求代理或额外认证，请联系管理员提供适用入口，不要通过关闭证书校验绕过连接问题。

<a id="return-fields"></a>

## 返回值与返回字段表

各业务页在操作小节用「返回」段说明该操作交付什么：一行返回形态，加一张返回字段表。约定如下，各页不再重复。

- 返回内容原样保留服务端结构：成功返回服务端 JSON，空成功响应为 Python `None` / JSON `null`；不统一加 `data` 包装、不统一改名，见[输入、输出与文件](#输入输出与文件)。
- 返回字段表表头固定为 `英文字段|中文名称|JSON 类型|单位|业务含义|备注`。`英文字段` 写相对返回根对象的完整路径：`.` 表示对象层级，`[]` 表示数组元素，返回根是数组时路径以 `[]` 开头；返回根本身就是该结构（如单个产品、单份持仓表）时，容器行的 `英文字段` 写 `（根对象）`；动态键写成 `{占位符}`（如 `{year}`、`{份额}`），并在表前说明它不是实际 JSON 键。
- `业务含义` 写该字段的取值或容器结构；`备注` 先写返回条件——`恒返回`、`随父级返回`（父级存在且该项有效）、`由参数选择`、`由数据决定`（只有部分来源、部分日期或部分分支有值）——再写该操作特有的边界（只读、不含某键、`0` 的含义）。
- `type / null` 表示可能返回空值；缺失键、`null`、空对象与空数组都不等于数值 `0`，不能自行补值。
- 元素结构若已在字段页或本页其它小节有字段表，返回表只列键名与最简形状（必要时附类型或格式，如 `date`(YYYY-MM-DD)、`source`(枚举)）并链接该表，不复制字段释义、单位口径与公式；字段的完整业务含义仍以字段页为唯一来源。
- 返回为 `None` 或空响应的操作不给表，只在「返回」段写一句话。

### 通用返回结构

以下结构在多个业务页出现，定义只写在这里，操作小节链接引用。

<a id="task-result"></a>

#### 任务终态 JSON

写操作与长耗时任务可能返回任务终态 JSON（等待与结局见[等待任务与判断完成](#等待任务与判断完成)）。字段如下：

|英文字段|中文名称|JSON 类型|单位|业务含义|备注|
|---|---|---|---|---|---|
|`status`|任务状态|string（枚举）|—|`SUCCESS` 表示任务完成，`FAIL` 表示失败，运行中为 `DOING`、`PENDING` 等|只把失败终态当作失败；等待超时抛 `wait_timeout`，不代表任务取消或失败|
|`progress`|任务进度|number|0 到 1|服务端上报的进度比例|运行中才有意义|
|`data`|任务结果|object / array / null|—|任务产物，结构随各操作|不自动拆包；`status` 为 `FAIL` 时可能是失败原因文本|
|`message`|任务提示|string / null|—|服务端说明文案|运行中或失败时出现，成功终态可能没有该键|

<a id="download-result"></a>

#### 下载元数据

`download` 与各类文件导出在成功落盘后返回客户端元数据，不返回文件内容：

|英文字段|中文名称|JSON 类型|单位|业务含义|备注|
|---|---|---|---|---|---|
|`path`|落盘路径|string|绝对路径|本次实际写入的本地文件路径|由 `output` / `--output` 决定，不复用服务端文件名|
|`size`|文件字节数|integer|字节|本次实际写入的字节数|与落盘文件核对；`0` 不代表内容完整|

<a id="write-result"></a>

#### 写入结果

写操作的返回按接口原样交付，最常出现的字段：

|英文字段|中文名称|JSON 类型|单位|业务含义|备注|
|---|---|---|---|---|---|
|`effect_count`|实际影响条数|integer|条|本次新增、修改或删除实际命中的记录数|`0` 表示没有命中或内容未变化，不代表请求失败；按日期或批量删除时 `0` 的具体含义见各操作说明|
|`insert_id`|新建记录 ID|string / null|字符串 ID|新建记录的 ID|只有创建类操作返回|

<a id="item-errors"></a>

#### 逐项失败容器

批量写入的返回里出现逐项结果时，客户端据此抛 `partial_failure` 并保留完整结果（见[输入、输出与文件](#输入输出与文件)）；`effect_count` 与非空错误数组可以同时存在，已成功项不回滚：

|英文字段|中文名称|JSON 类型|单位|业务含义|备注|
|---|---|---|---|---|---|
|`err_msg`|逐项错误说明|array（string 元素）|—|按提交顺序说明哪一项为何失败|非空即抛部分失败异常|
|`err_msgs`|逐项错误说明|array（string 元素）|—|同上；字段名随接口不同|非空即抛部分失败异常|
|`error_messages`|未写入原因|array（string 元素）|—|按日期或按项说明未写入原因|非空即抛部分失败异常|
|`detail`|逐项处理结果|array（object 元素）|—|元素含 `tag_id`、`effect_count`、`success` 与失败时的 `error_msg`|当前只有标签批量写入使用；存在 `success` 为 `false` 的项即抛部分失败异常|

## 输入、输出与文件

- Python 接收原生 dict/list/bool；日期用 `YYYY-MM-DD`。query 列表会编码为逗号分隔，布尔编码为小写 true/false。
- Python 与 CLI 的调用形式、参数写法与离线发现见[调用约定](#python-与-cli-调用约定)。结构化导入示例：`--input @trades.json`；文件导入：对应文件方法的 `--file-path`（如 `trades upload-intraday-file`、`trades upload-settlement-file`、`custodian-events upload-file`），不把 Excel 作为 JSON 参数。`trades.upload` 只接收 `data`，文件不再走它的入参，因此互斥由方法签名保证，不靠调用方自觉。其他列表参数示例 `--fields '["date","total_equity"]'`、`--resources '["授权测试产品"]'`、`--unit-event-ids '["6a1f…"]'`；布尔参数示例 `--drilldown true`。
- CLI 业务操作成功时将 JSON 写到 stdout；失败 JSON 写到 stderr，退出码非零。Python 抛 `HarnessError`，可读取 `code`、`status`、`details`，错误文字用 `str(exc)`；`exc.to_dict()` 及 CLI 错误 JSON 使用 `error`、`message`、`status`、`details` 键。服务端响应、任务 ID 和请求位置等诊断随错误保存，部分成功项仍需单独核对。离线 `--help` 输出帮助文本，`schema` 输出 JSON。
- 成功原样保留服务端JSON；空成功响应为 Python None / JSON null。不强制所有列表加 data 包装，也不统一改名：实际 `trades.list` 中记录主键为 `_id`，结构化流水写入结果的记录ID为 `id`。
- 批量返回有 err/err_msg 等逐项错误时抛部分失败异常，details 保留完整结果，包括已经成功的记录。该错误不是事务回滚；应按结果修复失败项，避免重放全批。
- 下载必须指定 `output` / `--output`，父目录需存在且可写，目标文件不得已存在。成功返回路径和大小，不向 stdout 输出二进制内容。下载中的文件可能已经可见，不能以“文件存在”作为下载完成依据。失败时检查错误详情；若有未清理的部分文件，应确认是本次下载后再处理，并为重试指定新的输出路径。

## Agent 遇到问题时怎么做

|问题|应采取的行动|
|---|---|
|目标不存在或名称有歧义|核对工作空间和权限，读取候选后使用唯一 ID；不要创建一个同名对象来绕过错误|
|报错 `resource_not_found`（选择空间时）|先区分来源：未指定空间且发现列表为空，说明当前用户没有成员空间，请管理员处理成员关系；`workspaces.use` 的目标 ID 未命中，则复查 `list` 并选择正确成员 ID，原选择保持不变。成员关系不代替 AMS 权益；不要猜 ID 反复试探|
|报错 `API Key 无效` 或 401|业务接口返回 `http_error`（HTTP 401，`WWW-Authenticate: Bearer`）。令牌缺失、过期、被撤销或不属于该环境；重新运行 `rqamsh auth`，或用 `--token`/`RQAMSH_TOKEN` 临时注入。不要伪造用户头或关闭证书校验；只读联调的做法见 `tests/README.md`|
|权限不足|错误码为 `permission_denied`，来自平台（客户端不预判读取级别）：向用户说明缺少的操作权限，按[逐操作最低权限级别](permissions.md#逐操作最低权限级别)确认需申请的级别，请资源所有者或管理员授权；不要更换为猜测的用户 ID|
|导入部分成功|记录已成功记录及失败原因，只修复失败项；对会覆盖整日/账户数据的文件导入，先重新确认完整文件与覆盖范围|
|上传完成但净值尚未更新|产品用 `products.compute_state` 检查估值状态，再按同一业务日期读回；产品组查询仍可能等待结果|
|等待超时|保留任务 ID、目标、请求参数及错误详情；先确认原任务结果，不能把超时当作取消后重新写入|
|新产品头寸报表或指标不可用|核对真实起始日、初始资金/份额、导入数据及计算状态；必要时请管理员处理。不要编造历史日期或资金流水来消除错误|
|下载失败|根据错误详情区分任务失败与本地文件问题；文件存在不说明内容完整|
|其他 AMS 错误|向用户说明未完成的步骤，保留错误码、文字、状态及详情供定位（CLI 为 `error/message/status/details`）；不要用零值或空成功结果代替错误|
