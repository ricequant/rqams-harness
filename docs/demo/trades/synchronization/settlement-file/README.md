# 只有日终结算文件：盘中能看头寸，不等于成交已齐

[返回流水处理场景](../../README.md)

混合数据源产品已有可读的估值起点，指定交易账户没有日内成交文件，也没有独立的盘中成交同步来源。该账户的券商流水要到交易日 D 收盘后才到；托管估值报告也可能更晚。运营上午问「今天的成交和净值是否都已更新」，盘后又需要确认实际结算成交进入估值。盘中与盘后不能用同一完成结论。

## 1. 盘中先给有边界的答案

用 [products.get](../../../../products.md#get) 核实工作空间内的唯一产品、`data_source=trade_and_valuation_report`、`auto_overwrite`、已配置的账户及业务日期。留存 D 日前核实过的[头寸报表](../../../../balances.md#get)作为起点；已有的现金、持仓与份额不是要重新导入的当日流水。

确认券商的交付安排，并按[流水查询](../../../../trades.md#list)查 D 日指定账户的当前有效流水。尚未收到文件时，流水列表为空只说明这次查询没看到记录，不证明全天没有成交；有其他资金或系统生成记录也不证明当日券商成交已齐。若用户需要盘中头寸，单独读取实际实时截面并核对 `date`，注明该账户的当日交易输入尚未齐备。最新历史结果可以明确日期后作为参考，不能顶替实时结果。未就绪时按[同日期等待与缺口处理](../../../../connection.md#unready-inputs)说明，不把缺项补成零，也不编造盘中成交文件。

## 2. 盘后收到文件，先确认它是可替换的完整结算版本

核对文件与指定账户的 `broker`、账号及交易日，使用该通道支持的日终结算模板，例如 RQ 通道的日终结算工作簿。文件应是批准范围的完整结算明细，不是截屏、任意 CSV、与上版的差额，也不是估值报告。查文件各行的交易日、代码、方向、数量、成交价、费用及币种；夜盘日期和基金后缀以对应通道规则为准。一个文件如果混入其他交易日或账户的数据，不提交到只获准的单日单账户范围。

本例虽然预期该账户此前没有同日券商成交，仍应在上传前按日期、账户及获准的单元筛选读全现有流水并本地留存，另存原始结算文件、来件版本和交易日。如果出现既有日内或 OpenAPI 成交，须先核对是否允许同日接管，见[日内与结算接管](../intraday-and-settlement/README.md)。如果已有结算记录，认清这是同日结算修订而非新增，先核对版本、明细差异和替换授权。[日终结算文件导入](../../../../trades.md#upload-settlement-file)按合法行日期、产品、账户及可选资产单元替换当前有效的 `settlement_upload`、`intraday_upload`、`open_api` 流水；解析出尚未登记的自定义标的时一并创建。若文件涉及未获准的标的创建或未解释的标的，先停止确认。

资产单元是覆盖范围的一部分，不能按账户名称推定。指定单元时用 [asset_units.get](../../../../asset_units.md#get) 核验归属并显式传 ID；替换仅匹配该单元，省略参数仅匹配未绑定单元的旧有效记录，不是替换账户全部单元。接口不接收业务日期白名单，须在上传前确认文件全部交易日都在授权内。查询与下载按成交自然日，夜盘备份和核验按[自然日查询与交易日替换](../intraday-file/README.md#trade-date-coverage)扩大到全部可能自然日后再筛交易日；下文单日示例仅适用于本次股票日盘。

## 3. 导入，然后区分任务、登记和估值各自的结果

以下片段在[已连接的 Python 会话](../../../../connection.md#建立连接)中执行。`product_id` 取已核实产品的 `id`，`account` 取产品内该账户的 `accounts[].name`，`settlement_file_path` 是已核对的通道结算工作簿本地路径。`trade_date` 是该文件的交易日 D；`asset_unit_id` 是已核对的资产单元 ID，只有授权确实覆盖账户范围时才用 `None`。

```python
settlement_receipt = rqamsh.trades.upload_settlement_file(
    resource=product_id,
    file_path=settlement_file_path,
    account=account,
    asset_unit_id=asset_unit_id,
)
```

1. **导入任务完成了吗？** 保留终态及 `data` 内的 `effect_count`、`err_msg`、`confirmation_id`。`status=SUCCESS` 只说明任务完成，不能跳过逐行结果。有凭证时用 [confirmations.get](../../../../confirmations.md#get) 对照解析和登记条数、实际登记日期及失败原因。
2. **结算明细成为有效输入了吗？** 复查与写前一致的查询范围，核对 `total` 并取全分页。对照文件里的各笔数量、金额、费用、交易日、币种和代码，确认结算成交来源为 `settlement_upload`；核实既有非目标记录未被误认成结算成交。没有合法行、登记 0 条或没有匹配凭证，不能直接说「无成交」或「整份结算已登记」。券商明确回报无成交时，可将该外部回报与系统当前记录分别说明，不用上传空文件来证明。[流水字段](../../../../fields/trades.md#trade)可用于识别各来源及成交字段。
3. **估值跟上了吗？** 检查 [products.compute_state](../../../../products.md#compute_state) 后，读回交易日和用户关心的后续日期。若 D 仍是北京时间当天，`balances.get(date=D)` 读的是实时截面；要确认 D 已形成的历史估值，须等该日进入历史查询范围，并核实返回日期。以起点和有效成交解释数量、现金及成本，再用实际估值价检查市值及[净资产、份额、单位净值](../../../../fields/balances.md#balance-calculation)。若缺价格、资金事件或结果未就绪，只交付已确认部分及其限制。

```python
effective_trades = rqamsh.trades.list(
    resource=product_id,
    start_date=trade_date,
    end_date=trade_date,
    account_names=[account],
    asset_unit_ids=[asset_unit_id] if asset_unit_id is not None else None,
)
state = rqamsh.products.compute_state(resource=product_id)
snapshot = rqamsh.balances.get(resource_or_resources=product_id, date=trade_date)
```

## 4. 异常时保住原始证据，别让修复变成第二次覆盖

- **逐行错误或部分成功：** 任务正常完成且含逐行错误时，有合法行的交易日仍执行范围替换，只登记该日合法行；没有合法行的交易日不替换，客户端部分失败异常不撤销已完成替换。保存[异常详情](../../../../connection.md#item-errors)、文件行号和凭证，重查当前有效流水。修复时把确认正确与修正后的行组成有授权的完整结算文件，先比对完整范围，不孤立重传失败行，也不另行清空流水。
- **中断、超时或结果未知：** 保存原文件、提交时间、目标范围、任务标识（如有）和最后诊断。有凭证时查凭证；无凭证时按本次操作时间用 [confirmations.list](../../../../confirmations.md#list) 查可能的批次，并以账户、来源、文件与有效流水交叉核对。不因一次空查询认定原请求未生效，也不盲目重传。
- **已过授权范围、封账或渠道不符：** 保留拒绝原因，停止本次写入。需要调整日期、账户配置或授权的，回到实际业务资料和对应的审批，不换目标来规避错误。

## 5. 报告更晚到时，结算与校准分别交付

对盘后结果可以说「该账户 D 日的结算文件已按完整明细核对，估值已读回」——前提是第 3 节的证据都成立；托管报告仍未到时，不能加上「与托管净值一致」。报告后来到达，先找它的业务日并比较同日头寸；对 `auto_overwrite=false` 的混合产品，仅保存报告不会校准估值。确需采用时单独授权，按[迟到报告校准](../valuation-report/README.md)检查采用状态、报告日和后续估值。报告是截面，不是盘中缺失成交的逐笔补录，也不能反证盘中成交早已齐备。

## 6. 实际短历史验证：没有日内导入，也能直接接入结算

本轮另建独立混合教学产品，从 06-26 的现金报告起点接入 06-29 的 RQ 通道完整结算文件，未先提交任何日内文件。文件人工设定平安银行买入 100 股、10 元，卖出 40 股、12 元；两笔佣金各 5 元，印花税和其他费明确为 0。这些费用是教学输入，不代表真实券商收费默认值。

|核验业务日|有效成交及来源|股票数量|现金（元）|净资产（元）|
|---|---|---|---|---|
|06-29|两笔，均为 `settlement_upload`|60|999,470|1,000,084.40|
|06-30|沿用同一结算输入，无新增成交|60|999,470|1,000,073|
|07-01|沿用同一结算输入，无新增成交|60|999,470|1,000,079.60|

实际回执无逐行错误；原文件列和行、回执、检查点及证券估值价见[证据](../../evidence.json)的 `lanes.settlement`。后续净资产不同来自各日返回的估值价，不是重复导入成交。本轮未实际观察盘中缺件时的实时截面，不能倒推当时已无成交或当天已有完整净值。

**验证边界。** 只有上述短历史 RQ 文件路径实际执行；其他通道、夜盘、跨币种、资产单元、修订结算文件与部分失败分支不据此视为已验证。盘中交付边界按真实来件条件判断，不冒充实际盘中、盘后时点对照。
