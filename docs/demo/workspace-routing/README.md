# 定位空间与目标产品

业务请求：“帮我核对示例产品的估值。”第一步不是调用对账接口，而是确认**在哪个部署、哪个空间、哪只产品、哪一天**。产品名称相同，不代表核算对象相同。

本页说明核心案例共用的定位思路；连接与成员空间规则以[连接说明](../../connection.md#token-auth)、[工作空间](../../workspaces.md)为准。

## 先确认连接，再解析对象

1. 使用已授权的连接与令牌；私有化部署要明确服务地址。令牌从受限文件或运行环境读取，不贴入对话、脚本或命令历史。
2. 用 `workspaces.list` 查看当前用户所属空间。用户已明确目标空间就核对其 ID；只给名称且重名时，不能自行挑选。未明确目标时遵守客户端默认规则，不额外强制用户选择。
3. 用 `workspaces.use(workspace=...)` 选择已明确的成员空间；空间选择只改变路由，不增加 AMS 权益或资源权限。
4. 在选定空间用 `products.get(resource=...)` 解析目标；核对返回的产品 ID、名称、数据源、账户和日期配置，后续固定使用该 ID。名称不能唯一解析时，依据用户提供的标识消歧；确需展示候选时才用 `products.list`，不为单产品任务先遍历全空间。
5. 确认业务日期与所需操作权限，再进入[对账案例](../reconciliation-controls/README.md)。可读产品不等于能执行对账查询或修改输入。

## 返回结果怎样改变下一步

|观察|判断与处理|
|---|---|
|用户没有成员空间|没有可用成员分区；停止，不把它直接解释成令牌无效|
|未指定目标且没有可沿用的保存空间|按服务端成员数组首项作为默认；不排序、不按权益筛选|
|默认空间的业务请求被拒绝|保留拒绝，不逐个切换寻找“能用”的空间；核对目标及权限|
|显式目标不在成员列表|停止，请求正确成员权限或纠正目标；猜 ID 或改请求头不能授予权限|
|切换空间后出现同名产品|重新解析并核对产品 ID；不复用旧空间的资源标识或查询结论|
|产品不可见或无权限|报告无法核实；不把“看不到”当作产品不存在，也不换同名产品继续写入|

成员关系、AMS 权益和产品权限是不同层次，不能由某一次读取成功互相推断。对账相关读取的权限要求见[对账调用约定](../../reconciliation.md#api-使用约定)。

## 可选：观察空间切换的受控演示

[脚本](run.py)在同一进程中读取成员列表，观察默认选择，并在两个显式成员空间之间切换，核对资源归属。它只读业务数据，不创建产品；不要求成员数量或可见产品数量等于某个固定值。

```console
python docs/demo/workspace-routing/run.py --base-url https://ams.example.com --workspace-id <空间A的ID> --other-workspace-id <空间B的ID> --output workspace-result.json
```

两个空间 ID 必须来自当前用户的成员列表；输出路径必须尚不存在。地址和 ID 均应替换为实际已授权的目标。脚本输出用于本次运行检查，不应复制含身份、成员资料或资源信息的原始报告到公开文档。

## 换个条件，如何处理？

- 用户明确指定另一个空间，但本地保存了旧空间：哪一个应当优先？
- 产品读取成功，对账查询却被拒绝：可以宣称“没有差异”吗？
- 两个空间各有同名产品：哪些已知标识能证明本次处理对象没有串空间？
