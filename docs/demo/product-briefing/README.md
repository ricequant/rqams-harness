# 单产品综合分析：从一句需求到可交付简报

用户说：“帮我看看示例指增一号截至今天的净值、前十大持仓、行业分布、风格暴露、主要风险，以及与昨天相比的变化。”

这句话包含六个问题，以及一个贯穿它们的比较轴（与昨天相比）。本案例演示：怎样判断日期与对象、怎样为每块选口径、怎样组织取数、怎样判断两块结果能不能比，以及什么情况下只能说“这一项今天给不出”。下文用虚构产品“示例指增一号”、构造日期与构造数值说明判断；它们是教学材料，不是任何环境的真实回执。

产品名是用户的描述，不是配置证据。名称里的策略或风格词不能证明该产品配了什么基准、什么策略类别，也不能证明实际暴露。判断一律回到 `products.get` 的配置与实际返回。本案例不依赖运行脚本即可完成；文末的 `run.py` 是覆盖范围更窄的参考实现。

## 1. 日期与“昨天”

**今天。** 按北京时间确定请求时间并记录。`balances.get` 不传日期或传当天，是实时语义：即使交易时段已结束，也不等于结算归档完成。要记录返回的 `date`、`update_time`，以及本次结果是实时截面还是日终结果（见[日期与实时语义](../../balances.md#日期与实时语义)）。同一时刻头寸、指标、风格暴露可能来自不同计算，不保证原子一致。

**昨天。** 用户已明确日期、上一自然日或上一交易日时，按明确要求执行；只说“昨天”“昨日变化”时，先读 `products.get` 的 `calendar`，优先按产品日历确定对照日。以本次要分析的目标业务日为 `T`，选择规则如下（含义见[估值日历](../../fields/products.md#calendartype)）；若当前结果实际日期不符，登记覆盖缺口，不以过期结果的日期重定比较区间：

|产品 `calendar`|默认对照日|日期证据|
|---|---|---|
|`exchange`|严格早于 `T` 的最近一个沪深交易日|用 [trading_dates](../../market_data.md#trading_dates) 查询真实交易日集合，不以减一天或周一减三天推算|
|`exchange_hkt`|严格早于 `T` 的最近一个沪深与港股共同开市日|核对两地交易日交集，不用单独沪深或港股日历代替|
|`natural`|`T` 的上一自然日|按自然日期计算，周末、节假日也读取该日独立结果|
|缺失或无法识别|暂不确定|核实配置；不能因新建产品默认 `exchange` 就替已有产品补日历|

`trading_dates` 目前只接受 `exchange`，不能传 `exchange_hkt` 或 `natural`。港股通分支需从已验证可用的行情源或可靠日历材料核对两地交易日后取交集；证据不足时明确“对照日不可核验”，不改用沪深交易日或自然日顶替。`previous_summary` 的日期只能作为候选，仍须核对是否符合产品日历和本次目标日期。

默认口径确定后，直接说明“按产品日历，与 YYYY-MM-DD 比较”，不要求用户再次确认已可由配置确定的信息。用户明确要自然日昨日时，即使产品按交易日统计，也读取指定自然日；额外的自然日或交易日对照另列，不混成一列。

选定对照日后再实际读取：无结果、未就绪或持仓不完整就按块登记缺口，不再向前挪日期直到找到有数据的一天。产品日历用于选择比较口径，不代表非交易日没有估值结果，也不改变服务端日收益的计算定义。

本案例主例把请求时间设为 `2026-11-06`（周五）22:50，产品配置为 `exchange`：按该日历，对照日为 `2026-11-05`，能返回独立日终结果；今天取 11-06 的收盘后实时截面，写明“交易结束不等于结算归档”，不称其为日终结果。

**跨周末变式**（请求时间 `2026-11-09` 周一）：

|项目|写法|
|---|---|
|`exchange`，用户未另指日期|以已核实的上一沪深交易日 `2026-11-06` 为对照，并明确标注日期；不必先查周日结果|
|`exchange_hkt`，用户未另指日期|查证上一共同开市日；即使沪深上一交易日为 11-06，也须核对港股同日开市，不能直接照搬|
|`natural`，或用户明确要上一自然日|读取 `2026-11-08`（周日），有独立结果就使用并注明；缺结果或不可比就列缺口，不改取周五|
|净值/持仓|两侧性质分别写（实时截面与日终结果不同）；缺持仓时该块不做变化|
|风险|两窗长度相同、端点不同，按产品日历核对预期样本；交易日口径的休市日不要求有样本，自然日口径不能因休市就跳过应有日期|
|风格|历史证据须匹配选定对照日及同口径时点；只到其他日期时注明实际日期，不能充当本次昨日变化|

逐块判断可比性，而不是只把报告标题统一成两天：净值看两个业务日、前十与行业看两份完整持仓、风格看模型与权重时点、风险看各自窗口与样本。

指标接口的 `end_date` 省略时取最近结算日，不等于用户说的今天，因此风险查询显式传区间并回报实际覆盖。

## 2. 先固定对象与口径

1. 解析一次产品，之后所有读取都传这个 ID；按[空间与产品定位](../workspace-routing/README.md)确认部署与空间，产品组与资产单元不是本案例对象。
2. 在同一次读取里看清 `calendar`、`benchmark`、`strategy_category`、`trading_start_date` 以及与估值、份额相关的设置（见[产品配置](../../products.md#get)）。
3. 核对权限：完整头寸视图、上一交易日概览、实时因子暴露与归因分属不同档（见[资源权限](../../permissions.md#逐操作最低权限级别)）。缺权限就登记缺口，不用摘要拼凑持仓。

名称与配置不一致时披露差异，按配置解释指标；要按用户口头说的指数另算，属于另一套数字，必须标“非产品配置基准”，且不改配置、不改基准。解析不到唯一目标时报告不可用，不用相邻产品补位。

## 3. 取数编排

|步骤|操作|依赖|并行|产出|
|---|---|---|---|---|
|1|解析产品与配置|—|串行一次|产品 ID、基准、日历、策略类别|
|2|按明确日期要求或产品日历确定对照日，并核对日历证据|步骤 1|串行|实际比较日期及采用理由|
|3a|读今日（或请求日）快照|步骤 1|可并行|净值、收益、持仓、敞口字段|
|3b|一次读取对照日完整头寸；只有已取得摘要而缺明细时才补读|步骤 2|可并行|对照日净值与持仓|
|3c/3d|风险指标：今日窗口、对照日同长度窗口|步骤 2，已确定两日日期与日历口径|可并行|指标与逐日样本|
|3e|实时因子暴露|步骤 1|可并行|当前截面|
|3f|可选：读取**已存在**的同口径历史暴露证据|步骤 1|可并行|对照日暴露|
|4|整理前十、集中度、行业、敞口与变化|步骤 3a、3b|—|由两份持仓派生，不再取数|
|5|汇总与交付|步骤 3~4|—|正文 + 缺口|

- **共享取数。** 前十、集中度、行业、占净值权重都用同一份持仓，不为每块重复调用；上一交易日概览不含持仓，只能用来定位日期。
- **统一预算。** 一个覆盖“解析 + 等待 + 加工 + 正文”的总截止时间；超时说明整份简报未完成，不是某个接口慢。
- **补读最小化。** 未返回的结果块按[未就绪与缺输入](../../connection.md#unready-inputs)有界等待，已成功的结果块不重放、不换日期顶替；中断等待不等于服务端失败，恢复时先复读原请求。
- **并发是执行策略**，统一见[连接与调用约定](../../connection.md#单字符串资源选择器)；本页不另立数字，也不把建议并发当接口限额。

## 4. 六块的口径、比较与缺项

|块|取什么、为什么|与昨天怎么比|缺什么就不下结论|
|---|---|---|---|
|净值|同一快照的单位净值、累计单位净值、当日收益；净值是估值结果，收益用服务端 `daily_returns`，不由净资产差或净值差反推（见[头寸字段字典](../../fields/balances.md#unit-net-value)）|净值本身是每份金额，收益是比率，分开比较；实时截面与日终结果的差异单独写|`daily_returns` 缺失就不报收益率|
|前十大持仓|同一快照的叶子持仓，筛股票多头按市值降序；指增的核心判断对象是股票组合，而期货名义市值、现金、应收应付不是同一种量|先各自取得两份完整持仓再排名；名单、权重、市值、数量分开列|任一日 `positions` 缺失或不是完整集合时不做名单变化，不把缺失当空仓|
|行业分布|复用股票多头的行业字段与市值，省掉重复取数与口径差；持仓行业口径固定（A 股中信一级、港股申万一级，见[持仓明细](../../fields/balances.md#position)）|统一分类标准后比百分点变化；占股票市值是组合结构，占净资产是对净值的影响|行业为空单列“未分类”不补零；有记录缺市值时只给已知金额小计并标覆盖|
|风格暴露|实时因子暴露的最新时点，按实际返回的因子键解释；它是持仓加权暴露减基准暴露的**主动暴露**，不是绝对暴露，也不是收益贡献（见[实时因子暴露](../../analytics/attribution.md#realtime_factor_exposure)）|只有当存在可读的同口径历史暴露（已存归因、已保存截面或用户材料）且模板、基准、持仓权重时点、底层因子日期都核对过时才并列给差值|证据不足只给当前截面，昨日变化写“不可核验”；不新建归因、不重算|
|主要风险|先后看结构（集中度、行业、衍生品名义敞口、风险资产敞口），再看日频波动、最大回撤、跟踪误差、几何超额回撤；绝对风险与相对基准偏离是两个方向|用同样长度的滚动窗，各自注明端点、样本覆盖与有效样本|有效样本不足或核心指标缺失时标不可验收，不写成“风险为零”|
|与昨天相比|不是独立的第七块：它是前五块的比较列，再按优先级汇总几条（本案例四条）|每块写清用的是哪两个日期、哪个窗口|某块不可比时，该块明写“本次不可比较”，不隐去|

需要单独记住的几点：

- **前十口径**：进入或退出前十不等于建仓或清仓；数量变化不等于交易，也可能来自送股、拆股、转股或划转，要证实得看权益记录与流水。权重分母是净资产，净资产不为正时改用绝对市值描述集中度。用户明确要“全品种绝对市值前十”是另一版口径，须标明它把名义市值与金额混在一起，不能与股票前十并列。
- **行业两个分母**：占股票市值一列合计 100%，占净资产一列合计等于股票占净资产（本例 82.75%），两者不是同一个合计，也不互为校验。行业超低配是另一条证据链，当前持仓不含基准行业权重，不能据此说“超配”。
- **风险窗口**：取 `[T−29, T]` 即含两端共 30 个自然日；窗口长度与样本日历是两回事。按产品日历核对预期日期，交易日口径不要求休市日样本，自然日口径不能只统计交易日。要写清请求区间、样本首末日、去重日期数、有限 `daily_returns` 有效样本数。指标链内部对缺失日收益有补齐规则（见[输入整理与日历](../../analytics/metrics.md#indicator-inputs)），所以返回的波动与回撤不能反过来证明样本完整，缺样本不自行补零。阈值没有业务依据时不贴风险标签。当前日尚未进入样本时写“最近可用日”，并说明本期变化不覆盖今天。
- **Beta 同名不同物**：风险指标里的 `beta` 是产品收益对基准收益的回归系数，风格序列里的 `beta` 是因子主动暴露，归因里的 `sensitivity` 又是另一套回归系数。报告里分开称呼，不互相替代。

## 5. 证据驱动的分支

|读到的结果|下一步|
|---|---|
|解析无唯一命中或不可见|给候选或说明不可用，不换同名对象|
|配置基准与用户口头说的指数不同|披露差异，指标按配置基准；另算版本标明“非配置基准”，不改配置|
|`calendar` 为 `natural` 或 `exchange_hkt`|分别按自然日或共同开市日选择对照；后者须有两地日历交集证据，不能仅查沪深日历|
|产品日历缺失、未知，或所需日历证据不可得|对照日不可核验，保留当前可核实结果，不猜日期|
|选定对照日没有返回独立结果|该块列缺口，不换成另一个有数据的日期；额外对照另标日期与理由|
|今日结果是收盘后实时截面|写清“未结算归档”，不称为日终|
|历史日期请求返回其他业务日|按错误处理，不当作请求日|
|某日 `positions` 缺失|不做名单、数量、行业、集中度变化；只有真实空列表才算空仓|
|部分持仓缺市值|结果 partial，小计与权重标“只覆盖已知金额”并给缺失条数|
|行业为 `null`|单列未分类，不补零|
|实时暴露只返回区间信息|不是零暴露；核对是否确有股票，稍后重读同一请求|
|历史暴露证据缺模板/基准/权重时点/因子日期任一项|不可比，只报当前截面|
|风险样本不含当前日|写最近可用日，本期变化不覆盖今天|
|有效样本不足或核心指标缺失|不可验收，不引用为结论|
|产品使用三级估值表覆盖|平铺持仓隐藏虚拟行、不保证完整集合，按[三级估值表与虚拟汇总持仓](../../fields/balances.md#level3-virtual-positions)单独核对|

### 6.8 勾稽关系

- 累计净值差 ÷ 前一日单位净值 = `(1.0700−1.0600)/1.0100` = `+0.9901%`，与净资产变化率一致，因为构造中份额不变。

## 8. 边界

- 全部数值为教学构造，不是任何环境的真实回执；真实任务重新取数并保留实际返回。
- 只读：不改产品、流水、估值、持仓、基准或策略配置，不创建、不重算、不删除归因。
- 只对单个产品成立；产品组与资产单元需要各自路径。
- 不把不同日期、不同来源、不同模型的数字拼成一条曲线；不把实时截面当日终结果。
- 比例只在分母有意义时计算；净资产不为正时不给占净值比例。
- 缺口分三类如实表达：`complete`、`partial`（有可核实结果但仍有真实缺口）、`failed` / `timeout`。不用部分结果宣布全部完成。
- 判断口径以[头寸报表](../../balances.md)、[净值与收益指标](../../analytics/metrics.md)、[持仓分析](../../analytics/holdings_analysis.md)、[业绩归因](../../analytics/attribution.md)、[市场数据](../../market_data.md)与当前 `rqamsh schema` 为准，本页不重述公式。

## 9. 可选脚本及其覆盖范围

`run.py` 一次输出 Markdown 报告与脱敏 JSON 证据：

```console
python docs/demo/product-briefing/run.py \
  --resource "授权测试产品" \
  --output  reports/product-briefing.md \
  --evidence reports/product-briefing.json
```

参数与安全边界：

- `--resource` 为产品 ID 或名称，只支持单产品；产品组或不可见目标会明确失败，不换同名对象。
- `--workspace-id` 在需要明确空间时使用；身份优先读环境变量，也可复用同一部署已保存的登录身份。
- `--deadline` 默认 180 秒，覆盖鉴权、接口等待、加工与报告生成，不只是接口时间。
- `--as-of YYYY-MM-DD` 可选，省略时读实时截面；未来日期被拒绝。
- `--risk-days` 默认 30，决定风险窗口长度；窗口内有效 `daily_returns` 不足两个时只登记缺口。
- `--attribution-id` 只读取一条**已经存在**的历史归因；脚本不创建、不重算、不删除。
- 输出路径必须是不存在的新文件，不覆盖旧报告与证据。

它的覆盖范围小于本案例：

- 前十按**全部品种的绝对市值**排名，期货、基金、存款会与股票混排；本案例的“股票多头前十 + 其他资产单列”需自行筛选持仓。
- 脚本仍固定查沪深 `exchange` 日历，并以概览或该日历确定上一交易日。仅适合作为 `exchange` 分支的参考，不会随产品 `calendar` 切换到自然日或港股通共同开市日，也不实现用户明确要求上一自然日的分支；不能用于代替本节前述日期选择。
- 另输出本自然周收益，而本案例主线没有这一项；反之，行业双分母、风险双窗口、跨周末变式、风格多来源证据核对，脚本都未实现。
- 风险只取请求日一个窗口，不产生“昨日风险变化”。默认 `--risk-days 30` 的请求区间是 `[T−30, T]`，含两端共 31 个自然日，与本案例 `[T−29, T]` 的 30 日窗口不同；今日实时截面也不会被标记为日终。
- 风格比较依赖给定归因 ID，只检查模板与“存在对照日那一行”，不核对基准、持仓权重时点与底层因子日期，因此通过检查**不构成可比证据**，其 T−1 差值只能当线索。
- 脚本是教学演示，不是通用诊断工具；它实际读到什么就写什么，不能替代真实业务结论。
