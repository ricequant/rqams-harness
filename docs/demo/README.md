# 用案例学习如何运用 AMS

这里不是功能目录，也不是需要依次完成的任务清单。API 文档回答“这个操作怎么调用”；这里用少量业务案例说明：**面对一个目标，先查什么、怎样解释结果、为什么选择下一步，以及做到什么程度才算解决问题。**

与 [Agent 业务翻译指南](../guide.md)分开阅读：指南维护跨任务规则，这里展示具体材料下的应用。没有匹配案例时仍按指南和业务页处理，不把案例当作固定执行模板或能力清单。

## 从四个核心案例开始

|学习案例|贯穿的业务问题|重点学习|
|---|---|---|
|[流水导入与历史更正](historical-trade-correction/README.md)|成交漏导或录错了，如何补齐并确认估值变化？|定位空间、产品与账户；区分缺失、重复、错误；选择导入或更正；检查影响日期，而不是只看写入回执|
|[估值表导入与结果核对](valuation-report-reconciliation/README.md)|拿到一份估值表，如何正确导入，并判断后续是否采用了它？|识别材料与日期；核对已有报告及覆盖授权；区分文件解析、报告保存、估值表采用和结果就绪|
|[对账：从差异定位到业务修正](reconciliation-controls/README.md)|某日为什么没对上，应该补什么，还是应当采用估值表？|串联空间、产品配置、对账状态、报告、流水、托管事件与头寸；按差异原因修正输入；复查后交付结论|
|[收益异常定位](returns-diagnosis/README.md)|股票当天上涨，为什么持仓仍浮亏、产品区间收益也低于预期？|区分行情涨跌、持仓浮盈浮亏与产品收益率；核对区间基点、净值/份额/分红与数据源；同口径仍不符时追到原始凭证与历史日期，授权修正后复查受影响区间|

四个案例不是互相孤立的步骤模板。对账发现缺估值表时进入导入案例，发现漏成交时进入流水案例；收益异常在同口径下仍不符、追到历史成交错日时，也回到流水案例更正。处理后都回到同一产品、同一业务日继续核对。空间和产品尚未确定时，先看[定位空间与目标产品](workspace-routing/README.md)。

## 怎么读，才不只是照抄操作

先按指南的[目标拆解](../guide.md#1-翻译要产出什么)判断对象、动作、范围、时间与读写，再选对应案例。通用[任务完成条件](../guide.md#task-readiness)、[写操作计划卡](../guide.md#6-写操作计划卡)和[结果翻译](../guide.md#7-结果翻译)只在指南维护；案例将它们落实为具体证据、变更字段、影响日期和前后结果，不再另列一套通用检查清单。

每篇末尾有条件变化后的思考题。把产品、日期或差异原因换掉后，仍能选择合理路径，才是案例希望传达的能力。

## 使用边界

- 例子中的产品名、对象别名、日期及金额用于教学；示意观察不是真实客户数据，也不是某个部署的执行报告。实际操作必须重新读取目标数据。
- 学习案例不是操作授权；实际任务仍按指南的[写入授权流程](../guide.md#6-写操作计划卡)执行，不能把案例中的确认当作用户对当前资源的确认。
- 同目录已有脚本是特定前提下的受控演示，不是自动诊断并修改任意产品的工具；可能创建、修改和删除演示对象，须先阅读各自运行范围。案例中的分支讨论不表示脚本已实现或验证全部分支。
- 本目录只保留上述核心案例及共用的空间与产品定位说明，不按 API 或业务主题铺开示例。其他业务直接查对应业务页，不要求为每个 API 配套独立 demo。

业务概念与主线见 [AMS 业务指南](../index.md)，通用判断与写入计划见 [Agent 业务翻译指南](../guide.md)。参数、返回结构、字段和公式仍以各业务页、`docs/fields/` 与当前 `rqamsh schema` 为准；案例不维护第二套契约。
