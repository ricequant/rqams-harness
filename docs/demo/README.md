# 用案例学习如何运用 AMS

这里不是功能目录，也不是需要依次完成的任务清单。API 文档回答“这个操作怎么调用”；这里说明：**面对业务目标，怎样拆解问题、选择并组织已有能力、根据结果决定下一步，以及什么证据足以交付。**

先按当前目标选择案例；需要通用判断时查本页后半部分。下列章节是按需使用的判断依据，不是每个会话必须重走的流程。信息充分时直接推进；案例中的具体路径也不是固定执行模板。

## 从业务目标选择案例

|学习案例|贯穿的业务问题|重点学习|
|---|---|---|
|[流水导入与历史更正](historical-trade-correction/README.md)|成交漏导或录错了，如何补齐并确认估值变化？|定位产品与账户；区分缺失、重复、错误；选择导入或更正；检查影响日期，而不是只看写入回执|
|[估值表导入与结果核对](valuation-report-reconciliation/README.md)|拿到一份估值表，如何正确导入，并判断后续是否采用了它？|识别材料与日期；核对已有报告及覆盖授权；区分解析、保存、采用和结果就绪|
|[对账：从差异定位到业务修正](reconciliation-controls/README.md)|某日为什么没对上，应该补什么，还是应当采用估值表？|串联产品配置、对账、报告、流水、托管事件与头寸；按根因修正输入，再复查|
|[收益异常定位](returns-diagnosis/README.md)|股票当天上涨，为什么持仓仍浮亏、产品区间收益也低于预期？|区分行情、持仓盈亏和产品收益；核对区间、净值、份额、分红与数据源；仍不符时追溯凭证与历史日期|
|[单产品综合分析与昨日变化](product-briefing/README.md)|指增产品截至今天的净值、前十、行业、风格和主要风险，与昨天相比怎样变化？|从业务问题选择指标；复用两日头寸、并行独立读取；对齐日期、分母、基准和样本，把变化解释成有依据的结论|
|[实盘产品规模汇总](live-product-scale/README.md)|当前有哪些实盘产品、各自多少规模，能否给出全量总额？|把范围与金额分开取证，固定产品集合，组织批量取数与缺项诊断，判断小计何时能成为总额|

案例可以衔接：对账发现漏成交时进入流水案例，缺估值表时进入导入案例；收益异常追到历史成交错日时，再进入历史更正。空间或目标尚不明确时，看[定位空间与目标产品](workspace-routing/README.md)。没有匹配案例时，按下面的通用判断与对应业务页组合能力，不要求为每个 API 配套一个 demo。

## 共用判断：按任务需要使用

<a id="使用方式用户说业务agent-读文档"></a>
### 接入与已有上下文

- **只问概念或能力**：直接解释，不为回答概念主动连接或触发登录。
- **需要自己的业务数据**：复用已有身份、目标部署与已明确的空间。只有实际需要建立连接且缺少身份时，才由 Agent 发起首个相关 CLI 只读命令；缺身份默认打开本机页面，用户在页面填 key，成功后继续原任务。没有具体查询但用户要求接入时，可用 `rqamsh workspaces list`。安装检查和离线 `schema` 成功不等于已连接。
- **连接失败**：按[连接与认证](../connection.md#建立连接)区分身份、地址、空间与资源权限，不先让用户提供工具已有的信息。空间选择遵循[默认工作空间与切换](../workspaces.md#默认工作空间与切换)；选择空间不增加权限。
- **本机登录等待**：保持命令运行，不因尚未返回就重开或杀进程。自动打开失败时将本次登录地址交给用户在同一台机器打开；超时后重新发起，不复用过期页面。只有明确远程、容器、无图形或无人值守环境才关闭自动登录并用安全注入；工具捕获输出或非 TTY 本身不能证明没有浏览器。令牌不贴进对话，不回显设置文件中的 key。已有安全凭据来源直接使用，不重复索取。
- **Python 多步业务**：已有身份时可直接使用；缺身份的 `rqamsh.init()` / `Client` 不自动弹页，本机首次先完成 CLI 登录。连接参数与环境变量差异见[建立连接](../connection.md#建立连接)。

是否讲解概念、是否询问角色，由当前任务决定；不强制先问角色、讲一个概念或每次只引入一个对象。同一任务里已明确的信息直接复用，目标部署、空间或业务范围改变时重新核实。文档按需读取；同一会话已读且未变化的规则不必重复全文阅读。

<a id="1-翻译要产出什么"></a>
### 目标拆解

执行前确定会影响操作或答案的六项；从用户请求、已有上下文和可用的只读信息中补齐，不把这张表当成逐项问卷。

|要素|需要确定什么|
|---|---|
|对象|核算主体或目标记录是什么，是否已定位到唯一 ID|
|动作|读取、导出、导入、更正、计算、封账或授权；是否包含多个动作|
|范围|单个对象、明确集合或全部可见资源；集合依据是什么|
|时间|业务日期、实时/历史、区间及日历；实际结果需要覆盖到哪里|
|读写|哪些能力只读，哪些会写数据、提交任务或产生持久化结果|
|验收与授权|需要哪些产物和证据，哪些副作用已授权，什么情况需补充确认|

### 组织取数与计算

先找依赖，再决定顺序：对象和配置决定日期、基准与分析口径；这些确定后，相互独立的只读分支可以并行。多个问题使用同一份数据时只取一次，例如前十、行业分布和集中度可共同使用完整头寸，不为每一项重新取数；需要专门分类、穿透或服务端口径时才增加对应查询。

多步查询复用同一连接与已解析的 ID；批量、并发及缓存策略统一见[连接说明](../connection.md#单字符串资源选择器)，不在每个案例重设数字。为整个任务留出等待、加工与交付的总预算；缺项只补读必要分支，已有结果可复用时不整批重来。效率以少做冗余工作为目标，不能靠跳过字段、日期或授权核验来换取“完成”。

### 对象与动作边界

按核算边界、来源和副作用判断，不按名字相似度映射。具体定义和操作以对应业务页为准：

- [产品](../products.md)是独立核算主体；账户是产品内的配置，不是可单独作为 `resource` 查询的全局资源。[产品组](../product_groups.md)用于成员汇总与分析，不是成员业务数据的批量写入口；已有批量读取可直接使用，不为汇总自动创建产品组。
- [资产单元](../asset_units.md)属于产品；资产单元持仓单只核对数量，不参与产品估值。系统头寸、[估值报告](../valuation_reports.md)、[产品持仓表](../positions_sheets.md)和[资产单元持仓单](../positions_statements.md)的来源及副作用不同，不能互相替代。
- 看结果与创建分析任务、查对账差异与改变对账状态、查计算状态与提交重算，分别判断读写。导出到本地不等于写回 AMS；一个请求含读写混合时，授权必须覆盖实际写入部分。
- [模拟交易](../paper_trading.md)不是实盘委托；不能将 Harness 的数据接口宣称为投资建议、下单或实盘执行能力。需要分析时按可用数据组织，不将分析包装成交易执行。

<a id="4-消歧规则"></a>
### 只澄清真正影响下一步的信息

歧义会改变对象、范围、口径或副作用时才提问；优先利用已有上下文和安全的只读查询，不能从文档或工具获得的信息再交给用户决定。

问题按依赖组织，而不是按对话轮次卡层：相互依赖的选择先解决上游，同一轮可以合并相关问题；相互独立的只读查询可以并行。用户已给对象、日期或目标时不要重复询问，也不要求动作、对象、时间和参数各占一轮。

名称多匹配时列出能区分目标的候选，不任选；范围不明时不擅自扩大到全部。角色只影响表达和关注重点，不代替实际请求、业务授权或服务端权限。对会改变数据的歧义，不能靠默认猜测继续。

### 时间与口径

- 回答区分请求时间、实际业务日期与更新时间；更新时间的含义查字段定义，不当作行情时间。
- “今天”默认北京时间；“最新”区分当前实时与最近结算，“本周”等区间说明边界。已有时间词不重复问；边界会改变结果且无法确定时才澄清。
- 用户已明确日期或自然日、交易日口径时按要求执行；只说“昨天”“昨日变化”时，先读产品 `calendar`，按产品日历选择对照日并写出实际日期。三类日历的选择及核验途径见[日期与“昨天”](product-briefing/README.md#1-日期与昨天)；缺配置或日历证据时不猜，选定日期缺数据时不偷偷换日。
- 实时不是历史日终，最近结算不能代替当日结果；夜盘业务归属按返回日期判断。交易日与自然日分开，按任务所用的产品日历或指标规则取区间，不按固定天数推算。
- 历史日期读回不符时保留请求与实际日期，不能冒充目标日；不传未来日期。日期参数契约见[头寸报表](../balances.md#get)。

<a id="task-readiness"></a>
### 任务完成条件

接口成功、写入回执或计算状态正常，都不单独证明用户目标完成。按本任务所需证据验收，而非要求每次执行所有检查：

|核验维度|交付依据|
|---|---|
|对象与集合|实际命中的 ID、授权范围与请求一致；批量逐项对账，缺项、失败项和范围外返回项不被静默忽略|
|日期与口径|实际结果覆盖目标日或区间，来源、基准、模板和日历满足当前比较所需条件，不混合不同口径|
|所需产物与字段|任务真正需要的结果已经取得；无关字段缺失不阻塞当前结论，相关字段缺失则限制结论范围|
|写后结果|不只核对被改记录，还按输入影响范围读回用户关心的后续结果；存在其他覆盖或来源变化时分段检查|
|解释证据|观察、核对关系与因果解释分开；截面差异和内部勾稽不证明完整输入或唯一根因|

缺项、运行态、失败与超时按[未就绪与缺输入](../connection.md#unready-inputs)区分，保留已取得结果，使用整体等待上限；只有确有计算状态证据时才说“正在计算”。明确失败停止无效重试；尚未就绪不补零，不换日期、不擅自改配置或重算以凑齐结果。到上限仍不完整时报告缺口及最后状态，不能把小计称为全量、把未就绪称为失败，或把超时当作服务端取消。

<a id="6-写操作计划卡"></a>
### 写入范围与授权

写前形成与风险相称的计划，说明对象、影响和验收；不是每次都把完整模板发给用户，也不因首次会话额外增加确认轮次。只读查重和诊断不单独索要业务授权。

```text
对象与范围：实际目标 ID；新建注明 ID 待生成；部署、空间和集合边界
日期与动作：业务日期、操作链、会改变什么
重复与覆盖：已有数据怎样处理，是否扩大覆盖或删除范围
授权：用户已明确授权什么；尚待确认的业务选择是什么
验收：读回哪些记录、字段和受影响日期
失败：如何保留诊断、确认副作用并处理部分失败或未知结果
```

用户明确要求创建产品、关键业务信息可确定且其余可用[公开创建默认](../products.md#创建时的推荐起点)时，复用该创建授权，查重、说明完整配置后创建并读回，不重复索要创建许可。名称冲突、关键信息不明、超出原指令或用户要求先审时，集中展示完整计划后一次确认。覆盖、删除、权限和封账等操作仍要有对应授权；业务授权不替代工具审批或服务端权限。

用户未提供账户信息时，按[创建时的推荐起点](../products.md#创建时的推荐起点)中的账户规则使用默认信息，不把“未提供”解释成要求空账户；读回时核对实际创建的账户。用户明确提供的账户配置按原指令与操作契约处理。

执行使用已解析且核实归属的 ID；产品组写入不自动广播到成员。写请求超时先读回副作用，不盲目重放。部分失败按目标操作区分逐项补失败项与按完整范围重传的覆盖式导入；不能一律只补失败项，也不能整批盲目重传。具体覆盖、重试及清理规则以该操作为准；不因名称相同认领未知创建结果或删除其他资源。

<a id="7-结果翻译"></a>
### 业务交付

|回答组成|需要说清|
|---|---|
|对象与时间|实际对象、业务日期/区间、实时或历史、来源与可用更新时间|
|已核验结论|用户关心的数字、单位、口径及所依据的结果|
|解释与依据|事实、已证实解释和待验证假设分开，不以相关性代替因果|
|完整性与下一步|覆盖范围、缺失、失败、未核验项及必要的后续动作，不用“成功”替代业务结果|

交付前对照实际数据核一遍关键结论：比较列的业务日期是否符合用户明确要求或产品日历选定的对照日，前十是否由完整集合重新排序、集合差是否与名单一致，行业比例的分母与合计是否对应。基准权重、阈值或因果证据缺失时，给出观测数值与限制，不把集中度或暴露直接定性为“极端”“违规”或已证实的收益原因。检验 Agent 是否掌握方法，要看它能否从入口自行选页、完成取数与核验；仅复述案例或运行脚本不能证明迁移能力。

字段含义与公式查[头寸字段](../fields/balances.md)和[指标说明](../analytics/metrics.md)，不凭字段名称推断。金额、份额、净值和收益率不混用；零、负值、`null`、缺失键和空列表分别按契约解释，空列表可以是真实的空集合，不一律视为缺口。计算状态、结算价标记、任务状态和逐项错误也分别解释，不用其中一个替代结果验收。

错误先按[连接与错误](../connection.md)分类再决定动作：连接或身份问题处理连接；权限与目标歧义不靠重试绕过；明确输入错误保留原文，不自行认定根因并修改；未知写入结果先核对副作用。对用户说明业务影响，不要求用户读错误码或用文档链接代替回答。

## 使用边界与能力分工

案例中的产品名、对象别名、日期和数值是教学构造，不是执行回执；实际任务重新读取目标数据。案例也不是操作授权，具体材料与分支不能代替用户对当前对象的授权。

同目录脚本是特定前提下的可选受控演示，理解和完成业务问题不以运行这些脚本为前提。部分脚本会创建、修改或清理演示对象，运行前阅读其范围；案例讨论的变式不表示脚本已实现所有分支。

业务主线与三类能力边界见[AMS 业务指南](../index.md)。`rqamsh` 提供数据读取与受控写入；筛选、集合对账、差分、汇总、编排和报告由 Agent 组织。参数、返回结构和公式以对应业务页、字段页及当前 `rqamsh schema` 为准，本页不维护另一份 API 契约。
